# 헬창 — 루틴 기록 설계

2026-08-11 · 1단계 (A+B+C: 루틴 기록 · 주간 계획/이월 · 진척 조회)

## 왜 만드는가

지금은 메모장에 이렇게 적는다.

```
등하는날
주운동 루마니안 6셋
(80-14,100-12,120-10,140-8,160-6,60-12)
보조 시티드로우 5셋
(47-20,55-18,62-16,70-14,78-12)
덤벨 풀오버 3세트
(25-14)x3
```

이 방식은 적는 데는 문제가 없다. 문제는 **읽는 쪽**이다. 3주 전 시티드로우를 몇 kg으로
했는지 보려면 메모를 거슬러 올라가야 하고, 늘고 있는지는 눈으로 세어야 한다. 못 한 운동을
언제 보충했는지도 남지 않는다.

그래서 이 앱의 목표는 "메모보다 적기 편한 것"이 아니라 **적은 것을 읽을 수 있게 만드는
것**이다. 입력은 메모만큼 빨라야 하고(그래야 계속 쓴다), 그 위에 추이·계획·이월이 얹힌다.

## 범위

1단계는 세 가지다.

- **A 루틴 기록** — 프리셋을 만들고, 오늘 세션으로 불러와, 실제 든 중량을 기록
- **B 주간 계획과 이월** — 날짜에 프리셋을 배정하고, 못 한 운동을 수동으로 미룸
- **C 진척 조회** — 종목별 중량 추이 그래프와 세트 표

다음 스펙으로 미룬 것: 식단 AI, 유산소 스크린샷 인식, 루틴 URL 공유. 데이터 모델에 자리만
남겨두고 구현하지 않는다.

### RN 전환을 위한 구조 규칙

"추후 RN 전환"이 목표이므로, **웹에만 있는 것을 UI 바깥으로 새어나가지 않게** 한다.
전환 시 버려지는 것은 `components/`와 `app/`의 JSX뿐이고 나머지는 그대로 옮겨간다.

- **`lib/` 는 순수 TypeScript다.** 세트 파서, 1RM·볼륨 계산, 날짜/이월 규칙, API 클라이언트,
  타입 정의. `window`·`document`·DOM 이벤트를 쓰지 않는다. RN에서 그대로 import한다.
- **데이터 접근은 `lib/api/` 한 곳을 통한다.** 컴포넌트가 `fetch`를 직접 부르지 않는다.
  RN에서는 이 파일의 base URL만 바뀐다.
- **레이아웃은 flexbox만 쓴다.** `grid`·`float`·`position: sticky`는 RN에 없다.
  간격은 `gap`과 padding으로 낸다.
- **Tailwind는 NativeWind가 지원하는 부분집합만.** 색·spacing·radius·타이포는 전부
  CSS 변수 토큰으로 두어 RN 테마로 그대로 옮긴다. `hover:`는 보조 수단으로만 쓰고
  동작을 그것에 의존하지 않는다(터치에는 hover가 없다).
- **라우팅 구조를 Expo Router와 맞춰 둔다.** App Router의 파일 규칙이 Expo Router와
  거의 같으므로, 폴더 구조를 그대로 옮길 수 있게 짠다.

## 데이터 모델

핵심은 **프리셋 · 세션 · 실제값의 3계층**이다. 프리셋을 오늘로 불러오면 깊은 복사가 일어나고,
그 뒤로 둘은 남남이다. 오늘 중량을 올려도 프리셋은 그대로고, 프리셋을 고쳐도 지난 기록은
안 변한다. 진척 그래프가 계획 수정에 오염되지 않는 이유가 이것이다.

```
User
  id, provider(kakao|google), providerId, nickname

Exercise                        종목 마스터. 변형까지 별개 행
  nameKo          "렛풀다운 (노멀그립)"
  nameEn          "Lat Pulldown"
  bodyPart        등 · 하체 · 가슴 · 어깨 · 팔 · 복근      ← 칩 필터 대분류
  targetMuscles   ["광배근"]                              ← 주 타겟, 세부까지
  secondaryMuscles ["이두근"]
  equipment       케이블
  mechanic        복합 | 고립
  force           밀기 | 당기기 | 정적
  level           초급 | 중급 | 상급
  category        근력 | 유산소 | 스트레칭 | 플라이오
  imageUrl        데이터셋 원본 URL (nullable)
  videoUrl        데모 영상 URL (nullable)
  defaultRestSec  기본 휴식 시간
  isCustom, userId                                        ← 직접 추가한 종목

  userId, date, presetId, memo

  userId, date, presetId(출처 기록용), title

```

### 몇 가지 결정과 그 이유

**세션은 "운동 시작"을 눌러야 생긴다.** 계획만 세우고 안 간 날은 세션이 없다. 미리 만들어두면
안 간 날마다 빈 세션이 쌓여서 통계가 오염되고, 지우는 일이 생긴다.

**요일 고정 스케줄을 두지 않는다.** 주마다 계획이 달라지므로 고정 요일은 매주 예외 처리
대상이 된다. 진짜 데이터는 `PlannedDay`의 **날짜**이고, 반복은 "지난주 그대로 가져오기"
버튼이 대신한다. 자동 복사는 하지 않는다 — 쉬는 주에도 계획이 생겨서 "안 한 운동"이 쌓인다.

**날짜로 배정하므로 이월과 같은 축에서 논다.** 미루기는 아직 시작하지 않은 `PlannedDay`의
날짜를 옮기고 `deferredFrom`에 원래 날짜를 남기는 것뿐이다. **이미 시작한 세션은 미룰 수
없다** — 부분 완료를 그대로 기록하고 닫으므로 미룰 잔여분이라는 개념이 없다. 자동으로
밀리지도 않는다. 한 번 빠졌을 때 주간 계획 전체가 연쇄로 어긋나는 것을 막기 위해서다.
미룬 날짜에 이미 다른 계획이 있으면 두 개가 나란히 뜨고, 무엇을 할지는 그날 고른다.

**부분 완료를 그대로 기록한다.** 6세트 중 4세트만 했으면 4세트가 기록되고 세션은 완료로
닫힌다. 안 한 세트는 `completedAt = null`로 비어 있다. 달성률은 계산해서 보여주되,
"미완료 세션"이라는 상태를 만들지 않는다.

**역할은 주운동 / 보조 두 종류**이고 순번은 저장하지 않는다. `보조1`·`보조2`는 같은 역할
안에서 `order` 순으로 화면에서 매긴다 — 저장하면 순서를 바꿀 때 둘이 어긋난다. 메모의 "보조3"처럼
번호가 건너뛰는 것은 순서를 바꿀 때 손으로 관리하던 흔적이라, 자동 번호로 대체한다.

## 종목 데이터

`free-exercise-db`(public domain JSON)에서 가져온다. 그런데 그대로 쓸 수 없는 지점이 둘 있다.

**1. 전부 영어이고 그립 변형을 안 나눈다.** 그래서 **한국어 종목명은 손으로 매핑한다.**
범위는 위 메모의 전 종목 + 부위별 대표 종목, **100개 안팎**. 800개를 다 번역하면 평생 안 쓸
종목이 검색을 어지럽힌다. 없는 종목은 앱에서 직접 추가한다. 목록에는 한국어를 크게, 영어를
아래 작게 같이 보여준다 — 영어가 이미지·영상 매칭 키이기도 하고, 헬스장에서 통용되는 이름이
영어인 경우가 많다.

**2. 세부 부위(윗가슴·아랫가슴)가 없다.** 데이터셋은 전부 `chest` 하나로 뭉뚱그린다.
이 구분은 종목을 매핑할 때 `targetMuscles`에 같이 채운다.

나머지 메타데이터(`force`, `level`, `mechanic`, `equipment`, `primaryMuscles`,
`secondaryMuscles`, `category`)는 **값의 종류가 유한하므로 사전 하나로 전량 자동 변환**한다.
근육 이름 21종, 장비 10종 남짓이라 사전이 짧다.

```
chest → 대흉근    lats → 광배근    traps → 승모근    triceps → 삼두근
push → 밀기       pull → 당기기    static → 정적
compound → 복합   isolation → 고립
beginner → 초급   intermediate → 중급   expert → 상급
```

이미지·데모 영상은 **파일을 저장소에 커밋하지 않고 원본 URL을 참조한다.** 레포가 붓는 것을
막고, 출처에 문제가 생기면 URL만 갈아끼우면 된다. 이미지가 없거나 직접 추가한 종목은 부위별
SVG 아이콘으로 폴백한다.

근육 그림은 [`react-native-body-highlighter`](https://github.com/HichamELBSI/react-native-body-highlighter)(MIT)를
쓴다. 앞/뒤 인체 SVG에 근육별 path가 들어 있는 컴포넌트다. RN용 패키지지만 `react-native-web`
없이도 SVG path 데이터만 뽑아 쓸 수 있고, 그렇게 하면 RN 전환 시 컴포넌트를 그대로 갈아끼우면
된다. 주 타겟은 `--accent`, 보조 근육은 `--accent-tint`로 칠한다.

## 화면

탭 넷: **오늘 · 루틴 · 기록 · 설정**.

### 오늘

이 앱을 여는 이유의 90%. 오늘 배정된 세션이 카드로 뜨고, 미뤄온 것이 있으면 앰버 왼쪽 띠와
함께 나란히 선다. 계획이 없는 날에도 프리셋을 골라 바로 시작할 수 있다.

카드를 열면 운동이 순서대로 펼쳐지고, 각 운동 아래 세트 행이 `80kg × 14`로 놓인다.
세트 행을 탭하면 완료 — 초록이 차오르고 **휴식 타이머가 자동으로 시작**된다(주운동 3분,
보조 90초, 종목별 조정 가능). 계획과 다르게 들었으면 행을 길게 눌러 고친다. 하단 진행률
바가 전체 세트 대비 완료 비율을 초록으로 채운다.

젖은 손으로 조작하는 화면이다. **터치 타깃 56px 이상**, 세트 완료 버튼은 그보다 크게.

구체적인 형태는 이렇다.

```
┌─────────────────────────────────────┐
│ 오늘  8월 11일 (월)                    │
│ ─────────────────────────────────── │
│ [✓ 완료] [오늘] [휴식] [금] [토]  ← 주간 칩 가로 스크롤
│                                     │
│  등하는날                    3/24세트  │
│  ████████░░░░░░░░░░░░░░░  진행바(초록) │
│                                     │
│  ┌───┐ 루마니안 데드리프트    [✎][⇄] │
│  │그림│ 주운동 · 6세트                │
│  └───┘                              │
│        80kg    14회            ⊙    │
│        100kg   12회            ⊙    │
│        120kg   10회            ○    │  ← ⊙ 완료(초록) / ○ 미완료
│        140kg    8회            ○    │
│                                     │
│  ┌───┐ 시티드 로우           [✎][⇄] │
│  │그림│ 보조1 · 5세트                 │
│  └───┘  − 5 +                       │  ← 세트 수 스테퍼
│        47kg    20회            ○    │
│                                     │
│  ＋ 운동 추가                         │
│ ─────────────────────────────────── │
│ [        운동 시작하기        ]  ← 초록 CTA
└─────────────────────────────────────┘
```

`[✎]`는 세트 편집(텍스트/스테퍼 전환), `[⇄]`는 종목 교체(같은 시트를 연다).
세트 행 오른쪽 원을 탭하면 완료 — 초록으로 차고 휴식 타이머가 뜬다.

### 휴식 타이머

세트를 체크하는 순간 자동으로 시작하고, **오늘 화면 하단에 고정된 바로 남는다.**
스크롤을 내려 다음 운동을 봐도 계속 보인다. 다른 탭(루틴·기록·설정)으로 이동하면 바는
사라지지만 타이머는 계속 돌고, 오늘로 돌아오면 남은 시간이 그대로 이어진다 — 타이머의
진실은 카운터가 아니라 종료 시각이라 화면을 떠나도 어긋나지 않는다.

```
┌─────────────────────────────────────┐
│ ⏱ 1:47   시티드 로우 · 2세트째        │
│ ████████████░░░░░░░░  [+30초] [건너뛰기]│
└─────────────────────────────────────┘
```

- 기본값 — 주운동 3분, 보조 90초. 종목별로 바꿔 저장할 수 있다.
- 남은 시간이 진행바로도 보인다(초록에서 줄어듦). 숫자를 읽지 않아도 감이 온다.
- `+30초`는 한 번 탭할 때마다 누적. `건너뛰기`는 즉시 종료.
- 0이 되면 진동(`navigator.vibrate`)과 소리. 백그라운드에서도 울려야 하므로
  종료 시각을 저장해두고 복귀 시 경과를 다시 계산한다 — `setInterval`은 탭이
  비활성이면 조여지므로 타이머의 진실은 시각이지 카운터가 아니다.
- 화면 켜둠(`navigator.wakeLock`)을 지원하면 켠다. 세트 사이에 화면이 꺼지면
  다시 켜서 잠금을 풀어야 한다.

### 운동 추가 시트

`+ 운동 추가` → 하단 시트. **프리셋 편집 화면과 오늘 화면이 같은 컴포넌트를 쓴다.**

- 상단에 가로 스크롤 부위 칩: `전체 · 등 · 하체 · 가슴 · 어깨 · 팔 · 복근` (선택 시 초록)
- 검색창 — 한국어·영어 양쪽으로 검색
- 최근 사용 종목 우선
- 세부 부위로 한 단계 더 좁히기
- 맨 아래 "직접 추가"

### 세트 편집 — 하이브리드

세트 편집기 상단에 텍스트 입력이 있다. `80-14,100-12,120-10`을 치면 아래 세트 행이
실시간으로 만들어지고, 반대로 행을 스테퍼로 고치면 텍스트도 갱신된다. `(25-14)x3` 같은
반복 표기도 파싱한다.

프리셋을 만드는 일(가끔, 정밀함이 필요)과 운동 중 기록(자주, 속도가 필요)은 성격이
정반대다. 메모를 그대로 붙여넣을 수 있으면서 운동 중엔 손가락만 쓰면 된다.

### 루틴

프리셋 목록과 주간 계획. 주간 뷰에서 날짜를 탭해 프리셋을 배정하고, `지난주 그대로
가져오기` 버튼 하나가 있다. 프리셋 편집은 오늘 화면과 거의 같은 구조인데 완료 체크가 없고
순서 드래그가 있다.

### 기록

종목을 고르면 상단에 종목 상세(근육 그림 · 메타데이터 · 데모 영상), 그 아래 그래프
(추정 1RM 선 + 볼륨 막대, 토글), 맨 아래 날짜별 세트 표.

- **추정 1RM** — Epley: `w × (1 + r/30)`, 그날 최댓값
- **볼륨** — `Σ (w × r)`, 완료된 세트만
- 신기록을 세운 날은 초록 점

중량과 반복이 같이 움직이기 때문에(`47-20 → 78-12`) 최대 중량 하나로는 늘었는지 판단할 수
없다. 두 지표를 같이 본다.

### PC에서 모바일 뷰

창이 넓으면 가운데 440px 프레임으로 렌더하고 바깥은 배경으로 둔다. 반응형으로 늘리지 않는
이유는, 늘려봐야 네이티브에서 쓸 일이 없는 레이아웃을 따로 유지해야 하기 때문이다.

### 오프라인

서버 DB를 쓰므로 헬스장 지하에서 요청이 실패할 수 있다. 세트 완료는 **낙관적 업데이트 +
로컬 재시도 큐**로 처리한다. 화면은 즉시 반응하고, 실패한 요청은 신호가 돌아올 때 재전송한다.
양방향 동기화가 아니라 단방향 재시도 큐라 부피가 작다.

## 디자인

### 팔레트 — 다크 전용, 초록이 주 컬러

```
--bg           #0B0D0C   거의 검정. 순회색이 아니라 옅은 초록 기운
--surface      #141715   카드 · 운동 블록
--surface-2    #1C201E   입력칸 · 눌린 면
--line         #262B28   경계
--ink          #F2F4F2   중량 숫자 · 제목
--ink-2        #B9C0BA   본문
--sub          #7E8781   라벨 · 캡션
--accent       #4ADE80   브랜드 · 주 동작 · 완료 · 진척
--accent-press #3CBB6A
--accent-tint  rgba(74,222,128,.12)
--amber        #E0A33E   미룬 운동 · 주의
--amber-tint   rgba(224,163,62,.12)
```

**초록을 쓰는 곳** — 로고, 주 버튼(운동 시작·세트 완료), 활성 탭, 진행바, 완료 체크,
신기록 배지, 그래프 선, 선택된 칩.
**안 쓰는 곳** — 본문 텍스트, 넓은 배경 면, 카드 전체 채우기.

**빨강을 쓰지 않는다.** 파괴적 동작은 색으로 경고하지 않고 확인 단계로 막는다. 삭제 버튼은
`--ink-2` 무채색이고, 누르면 확인 시트가 뜬다. 색보다 한 단계 더 밟게 하는 쪽이 실수를 실제로
막고, 다크 화면에서 빨강은 초록과 채도가 부딪혀 지저분해진다.

### 타이포

119-remix `globals.css`에서 **구조를 가져온다**(색이 아니라).

```
screen  16   화면 이름
title   15   섹션 제목
body    14   값 · 목록 항목
meta   12.5  라벨 · 캡션
micro   11   배지 · 타임스탬프
```

**중량 숫자만 예외로 한 단계 크게** 간다 — 이 앱에서 사람이 보러 온 것이 숫자다.
`font-variant-numeric: tabular-nums`로 세트마다 자릿수가 흔들리지 않게 한다.
이징도 가져온다: `--ease-out: cubic-bezier(.23, 1, .32, 1)`.

전부 Tailwind v4 `@theme` 블록의 CSS 변수로 정의한다. react-native-css가 이를 RN 스타일로
변환하므로 네이티브 전환 시 `className="text-ink bg-surface"`가 그대로 동작한다.

## 테스트

- **세트 표기 파서** — `80-14,100-12`, `(25-14)x3`, 공백·전각 문자 혼입, 깨진 입력.
  순수 함수라 테스트가 싸고, 여기가 깨지면 기록이 날아가므로 가장 촘촘히 짠다.
- **진척 계산** — 추정 1RM, 볼륨, 신기록 판정. 역시 순수 함수.
- **API 라우트** — 프리셋→세션 복사가 실제로 독립적인지(프리셋 수정 후 지난 세션 불변),
  미루기가 날짜와 `deferredFrom`을 맞게 쓰는지, 부분 완료가 정확히 기록되는지.

화면은 E2E 대신 수동 확인으로 간다. 1인용 앱에서 Playwright 유지비는 회수되지 않는다.

## 배포

미니 PC에 docker-compose(Postgres + 앱 컨테이너), GitHub Actions가 ssh로 배포한다.
Atti와 같은 방식이다. 미니 PC의 `~/servers/docker-compose.yml` 하나를 여러 프로젝트가
공유하므로, 워크플로에 `concurrency: hellchang-production`을 걸어 동시 배포가 서로를
밟지 않게 한다.

배포 순서 — 러너가 rsync로 소스를 `~/servers/hellchang/repo/`에 밀어넣고,
`docker compose up -d --build --no-deps hellchang-db hellchang-web`으로 해당 서비스만
올린다. 서버에 GitHub 자격증명을 두지 않는다.

**도메인은 Nginx Proxy Manager**가 붙인다. `hellchang.rheon.kr` → `hellchang-web:3000`
프록시 호스트를 NPM UI에서 한 번 추가하면 인증서까지 자동으로 잡힌다. 배포 워크플로는
컨테이너를 올리는 데까지만 관여한다 — NPM 설정을 코드가 건드리면 21개 서비스가 공유하는
설정을 망가뜨릴 수 있다.

**PWA** — manifest + 서비스워커(앱 셸 캐시), 홈 화면 추가, standalone 모드,
아이콘 192/512 일반·마스커블.

**환경변수** — `DATABASE_URL`, 카카오/구글 OAuth 키, 세션 시크릿.
2단계용으로 `S3_*`, `OPENAI_API_KEY` 자리를 `.env.example`에 남겨둔다.

## 커밋 규칙

Atti 컨벤션을 그대로 쓴다. `AGENTS.md`에 옮겨 적는다.

```
feat: 간단한 요약

- 바뀐 것 1
- 바뀐 것 2

필요한 경우 이렇게 구현한 이유
```

제목은 `타입: 요약` 한 줄. 본문은 `-` 불릿으로 무엇이 바뀌었는지 나열하고, **판단이
필요했던 부분만** 그 아래에 이유를 적는다.

타입 — `feat` 기능 · `fix` 버그 · `refactor` 동작 변화 없는 구조 개선 · `perf` 성능 ·
`docs` 문서 · `test` 테스트 · `build` 빌드·의존성 · `ci` 워크플로 · `chore` 그 외

하나의 커밋은 하나의 완결된 변경이다. 빌드가 깨진 상태로 커밋하지 않는다.
작업은 브랜치에서 하고 PR로 합치며, 머지 전에 시행착오 커밋을 정리한다.
